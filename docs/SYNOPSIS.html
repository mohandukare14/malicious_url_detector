6) Proposed Title: Zero-Day Phishing & Malicious URL Classification Using Machine Learning Analytics
7) Relevance:

The project falls under the specialized domain of Cybersecurity, Machine Learning, and Automated Threat Intelligence. In modern network ecosystems, email gateways and web browsers remain the primary ingress vectors for corporate data breaches, ransomware, and identity harvesting. Over 80% of enterprise security incidents begin with deceptive phishing links. Conventional defensive controls—predominantly static blacklists (such as Google Safe Browsing and DNS sinkholes)—are reactive in nature; they can only flag a domain after initial victims have been compromised and manual analysis reports are processed. Machine Learning revolutionizes this operational paradigm by enabling zero-day heuristic threat classification. By analyzing structural character distributions, domain entropy, and lexical token anomalies directly from raw Uniform Resource Locators, ML algorithms make instantaneous millisecond-level threat determinations without network latency or hazardous payload execution.

8) Introduction:

In today’s hyper-connected digital landscape, phishing attacks, credential harvesting, and malicious URLs represent catastrophic security and financial risks to both individual users and enterprise organizations. Cybercriminals exploit automated Domain Generation Algorithms (DGA), typo-squatting, and dynamic bulletproof infrastructure to deploy short-lived fraudulent domains within minutes. These malicious URLs mimic trusted banking portals, e-commerce platforms, cloud storage, and social networks (e.g., PayPal, Apple ID, Microsoft 365, Chase) using multi-level subdomain cloaking and character obfuscation. Furthermore, over 80% of modern phishing domains now acquire legitimate SSL/TLS certificates, rendering traditional browser padlock indicators ineffective. Consequently, there is an urgent industry requirement for an autonomous, lightweight, and high-accuracy Machine Learning pipeline capable of statically inspecting URL characteristics in real time before client connection establishment.

10) Objectives:
  1. Literature Benchmarking: To carry out a detailed analytical survey of existing statistical, heuristic, and neural network techniques for malicious URL and phishing classification.
  2. Multi-Dimensional Feature Engineering: To construct an automated feature extraction engine capable of deriving 19 lexical, structural, statistical, and Shannon entropy indicators from raw URLs.
  3. De-Biased Dataset Ingestion: To assemble a balanced benchmark dataset of verified benign and malicious domains with protocol parity (accounting for modern HTTPS phishing) to avoid shortcut overfitting.
  4. Ensemble Model Training & Validation: To develop, optimize, and cross-validate a depth-constrained Random Forest Classifier alongside a Logistic Regression baseline using 5-Fold Stratified Cross-Validation.
  5. Real-Time Threat Inference Tool: To deliver a serialized, production-grade CLI prediction utility offering sub-15ms threat classification, confidence percentages, and explainable risk diagnostics.
11) Proposed Work:

The implementation lifecycle comprises six systematic phases:

  1. Collection of Benchmark Datasets: Aggregating verified phishing streams from PhishTank and trusted corporate/academic domains from the Tranco Top 1M registry.
  2. Lexical & Shannon Entropy Feature Extraction: Computing component lengths, delimiter counts, digit ratios, IPv4 regex patterns, and character randomness metrics in under 2ms per sample.
  3. Exploratory Data Analysis & De-Biasing: Normalizing bare domains, balancing protocol distributions, and performing an 80/20 stratified train-test split.
  4. Model Architecture Selection: Setting up a standardized Logistic Regression baseline and tuning a 120-tree Random Forest ensemble.
  5. Model Training & Cross-Validation: Validating generalization capability using 5-fold cross-validation, logging Confusion Matrix, Precision, Recall, and ROC-AUC curves.
  6. Deployment & Real-Time Verification: Exporting the serialized model bundle (.joblib) and packaging a standalone CLI inspection tool.
